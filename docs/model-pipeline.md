# RefactorAI model orchestration

The chat now sends requests to a Node backend, not directly to the model provider.
UI components remain unchanged.

Browser → /api/chat → validation → secret redaction → code signals → knowledge retrieval
→ bounded context assembly → provider adapter → response validation/redaction → browser.

## Run

Requires Node 22.12 or newer. The backend has no npm dependencies.

1. Start backend: `node server/index.mjs`.
2. Install frontend dependencies and start the existing React application.
3. Local frontend configuration: `REACT_APP_BACKEND_URL=http://localhost:3001/api/chat`.
4. Run backend checks: `node --test server/test/*.test.mjs`.

The existing BYOK credential goes to the backend in an Authorization header. It is
forwarded only to the administrator-configured HTTPS provider, never placed in the
prompt or persisted on the server. The browser's existing localStorage behavior
remains. No raw chat, source or keys are collected for training or logged.

## What the intermediate layer does

- Rejects unsupported roles, empty/oversized messages and invalid conversation endings.
- Redacts common key formats, quoted secret assignments, Bearer tokens and private keys.
- Extracts fenced language labels and heuristic warning signals without executing code.
- Ranks a curated, versioned local knowledge base with deterministic lexical retrieval.
- Supplies up to four matching knowledge entries with analysis and a stable developer policy.
- Preserves the latest code intact; drops oldest history to meet a 48,000-character budget.
- Uses low temperature, a provider deadline, bounded active requests and safe error responses.
- Returns knowledge IDs and omitted-history counts for observability.

This is a baseline analysis and retrieval pipeline, not an AST parser, embedding
index, autonomous agent or guarantee of vulnerability detection. Character limits
are conservative application budgets, not exact model token counts. Redaction is
best effort. Submitted source still reaches the provider after processing.

## Deployment

GitHub Pages hosts static files and cannot run this backend. Deploy the Node process
separately behind HTTPS, set FRONTEND_ORIGIN to the exact frontend origin, then build
the frontend with REACT_APP_BACKEND_URL pointing to that backend's /api/chat URL.
Set HOST=0.0.0.0 if required by your host. Configure MODEL_API_URL and MODEL_NAME on
the server to select an available compatible model or your own trained endpoint.
Changing these values does not train a model.

CORS is a browser origin restriction, not authentication. BYOK avoids a shared
provider key; do not replace it with a public shared key without adding user
authentication, quotas and deployment-level rate limiting. Terminate TLS and
enforce request-body deadlines at the reverse proxy. Avoid logging Authorization
headers or request bodies. Rebuild/deploy the frontend after configuration changes;
the committed build/ assets are not regenerated by this change.

## Knowledge and training

Extend server/knowledge.json with reviewed domain guidance and stable IDs. Prefer
specific project conventions and verified examples over a larger generic prompt.
Retrieval changes inference context; it does not modify model weights.

To prepare actual supervised training data, create a JSON array with records:

```json
[{
  "approved": true,
  "source": "human-authored example, review reference",
  "license": "your confirmed reuse permission",
  "messages": [{"role": "user", "content": "Debug this minimal example..."}],
  "answer": "Reviewed correct answer with a fix and tests..."
}]
```

Run `node server/training.mjs reviewed.json work/dataset` to create train and
validation JSONL files. Every record requires explicit approval and provenance.
Inputs use the same orchestration policy as production, secrets are redacted,
duplicate inputs are removed, and a deterministic input hash assigns approximately
20% to validation. Small datasets may have an empty split; inspect counts before
training. Do not commit private datasets. Redaction does not replace human review.

No model-weight training is performed by this exporter. Train on your chosen
provider/infrastructure separately, measure correctness, regression behavior,
security and language quality against a held-out dataset, then configure MODEL_NAME
(and MODEL_API_URL when necessary). Keep a separate final test set outside training
and validation. Compare the existing and candidate model using identical prompts;
do not deploy a new model solely because training loss decreased.
